Ограничения S3

Последнее изменение: 27 августа 2026Открыть в Markdown

Мы рекомендуем загружать объекты размером более 1 ГБ с помощью сегментированной загрузки через S3 API или Swift API.

Лимиты хранилища и лимиты бакета вы устанавливаете самостоятельно.

Ограничения сущностей S3

  • Бакеты

  • Объекты

  • Заголовки

Максимальное количество бакетов в проекте2 000*
Максимальное количество бакетов с Virtual-Hosted адресацией в проекте100** (в рамках 2 000)
Максимальный размер имени бакета128 символов UTF-8
Максимальный размер политики доступа20 КБ
Максимальное количество объектов в бакетеНе ограничено

* В панели управления отображаются первые 1000 бакетов. Если бакетов больше, посмотреть полный список можно через API.

** Можно увеличить по запросу.

Максимальный размер объекта50 ТБ
Максимальный размер имени объекта1024 символов UTF-8
Минимальный размер данных для загрузки за один запрос0 байт
Максимальный размер данных для загрузки за один запрос5 ГБ
Минимальный размер сегмента при сегментированной загрузке1 байт
Максимальное количество сегментов при сегментированной загрузке10 000
Максимальный размер всех заголовков/метаданных на аккаунт/бакет/объект в теле запроса8 КБ
Максимальный размер всех заголовков/метаданных вида X-Account-Meta-$Name, X-Container-Meta-$Name, X-Object-Meta-$Name4 КБ
Максимальное количество заголовков на аккаунт, бакет или объект90
Максимальный размер имени заголовка64 символа UTF-8
Максимальное количество символов в значении заголовка256 символов UTF-8
Максимальный общий размер заголовка320 символов UTF-8 (64 символа + 256 символов)

Ограничения запросов API

Ограничения указаны для одного бакета. Если ваш профиль нагрузки превышает эти ограничения, мы рекомендуем распределять нагрузку между несколькими бакетами из расчета не более 250 запросов в секунду (RPS) на каждый бакет.

Если превысить ограничение, сервер вернет ответ с кодом 429 Too Many Requests и сообщением Rate Limit exceeded.

  • Swift API
