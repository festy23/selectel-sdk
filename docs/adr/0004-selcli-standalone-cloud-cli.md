# Создавать selcli как самостоятельный универсальный CLI

Заменено [решением о selectelsdk](0005-selectelsdk-common-cloud-library.md).

selcli предназначен для управления инфраструктурой Selectel из терминала
человеком или агентом и должен работать вне репозитория приложения-потребителя.
Его целевое покрытие определяется операциями облака, а не только потребностями
конкретного переноса. Специализация инструмента под один перенос ограничила бы
его дальнейшее использование другими проектами и агентами.

CLI предоставляет операции управления инфраструктурой. Выбор действий агента,
правила его автономности и оркестрация переноса относятся к вызывающему workflow;
они не определяют назначение CLI.

Целевые возможности включают чтение данных облака, получение состояния VM и
других ресурсов, создание и удаление ресурсов, биллинг, логи и метрики.
Управление секретами и ключами шифрования включается в пределах доступных
документированных API; наличие эквивалентов KMS и Lockbox подтверждается отдельно.

Покрытие ограничено документированными программными интерфейсами Selectel и
OpenStack. Внутренние API веб-панели и автоматизация браузера не являются
адаптерами CLI: они привязали бы его совместимость к устройству панели.

CLI реализуется на Go как самостоятельный бинарник с использованием официальных
Go SDK и прямых документированных API для недостающих операций. Python-заготовка
чтения инфраструктуры не задаёт архитектуру целевого инструмента.

В первую версию входят авторизация, проекты, VM, сети, диски, Managed Kubernetes,
DBaaS, Container Registry, DNS, S3, Secrets Manager и биллинг. Набор операций
внутри каждой группы и критерии его готовности определяются отдельно; перечисление
сервисов не означает подтверждённую реализацию или полное покрытие каждого API.

Основной формат ответа команд — JSON. Табличный вывод выбирается явно.
Машинный контракт должен позволять использовать CLI независимо от конкретного
агента; структура ответов и семантика ошибок определяются отдельно.
