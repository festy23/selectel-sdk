# Domain documentation

Layout: single-context.

Before exploring the codebase, read the root CONTEXT.md and relevant
decisions in docs/adr/. If a CONTEXT-MAP.md exists, follow its pointers
to the contexts relevant to the task.

If these documents are absent, proceed silently. Create domain
documentation through domain-modeling when terms or decisions are resolved.

Use the glossary's terminology in specifications, issues and code.
If a needed concept is missing, reconsider the wording or record the
gap for domain-modeling.

When proposing a change that contradicts an ADR, identify the decision
and explain why it should be reconsidered.
