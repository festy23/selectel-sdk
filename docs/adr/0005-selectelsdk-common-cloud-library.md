# Создавать selectelsdk как общую библиотеку управления облаком

Основным продуктом становится selectelsdk — библиотека, которой агент или
приложение пользуется для программного управления Selectel. Общая облачная
логика должна быть доступна вызывающему коду без обязательного CLI: привязка
этой логики к терминальным командам ограничила бы её переиспользование.
Это решение заменяет [выбор selcli](0004-selcli-standalone-cloud-cli.md).

Библиотека объединяет авторизацию и обновление доступа; выбор аккаунта, проекта,
региона и endpoint; обход страниц; ожидание операций, timeout и отмену;
единые ошибки и обработку неизвестного исхода; недостающие операции через
документированные API. Существующие SDK Selectel и совместимых протоколов
используются как строительные блоки. Цель — удобный для агента доступ к чтению,
состоянию и управлению ресурсами, биллингу, логам, метрикам и секретам в пределах
документированных программных интерфейсов.

Библиотека реализуется на Go. Основной интерфейс — типизированные методы по
сервисам с машинно читаемым каталогом возможностей. Общие гарантии концентрируются
в ядре; предметные параметры и действия сохраняют смысл API соответствующего
сервиса. Такой интерфейс позволяет непосредственно использовать существующие
Go SDK и не требует от вызывающего кода нового универсального языка операций.

Целью остаётся полное покрытие документированных API Selectel. Для каждой
операции каталог связывает официальный контракт, реализацию и статус проверки.
Общий HTTP-вызов сам по себе не засчитывается как поддержка операции.

Начальная разработка проходит через сквозные сценарии: инвентарь, один цикл
создания/чтения состояния/ожидания/удаления ресурса, биллинг и ограниченное чтение
телеметрии. Это проверяет общие гарантии до расширения набора методов по всем
сервисам. Точные контракты вызовов и критерии проверки определяются отдельно;
наличие SDK или метода не подтверждает работоспособность с облаком.

Аккаунт, проект и location задаются неизменяемым scoped объектом. Общие типы
scope, ошибок и receipts принадлежат библиотеке; предметные DTO официальных
SDK переиспользуются с явным поколением API и защищёнными sensitive fields.
CredentialSource передаётся явно; loaders profile/env/keyring вызываются
отдельно. Mutation возвращает факт принятия и известные refs; ожидание является
отдельным вызовом. Safe reads имеют ограниченные retries. Mutation повторяется
только при документированной гарантии replay; потерянный ответ без такой
гарантии остаётся неизвестным исходом.

Нормативный контракт, начальные сценарии и правила полного API coverage
определены в [спецификации selectelsdk](../modules/selectelsdk/README.md).
